# SplitEvents

Telegram Mini App для организации совместных мероприятий.

## Структура проекта

```text
/
├── index.html
├── app.js
├── README.md
├── css/
│   ├── base.css
│   ├── events.css
│   ├── layout.css
│   ├── menu.css
│   ├── profile.css
│   └── pages.css
└── js/
    ├── telegram.js
    ├── menu.js
    ├── profile.js
    ├── storage.js
    ├── events/
    │   ├── data.js
    │   └── read-state.js
    └── pages/
        ├── empty-state.js
        ├── event-card.js
        ├── events.js
        └── servers.js
```

## Где что находится

- `index.html` — HTML-каркас приложения и доступные разделы.
- `app.js` — запуск приложения, hash-маршруты и переключение страниц.
- `css/base.css` — дизайн-токены, сброс стилей и базовая доступность.
- `css/events.css` — оформление списка событий и карточек.
- `css/layout.css` — шапка приложения, основная область и безопасные отступы.
- `css/menu.css` — боковая навигация.
- `css/profile.css` — оформление профиля.
- `css/pages.css` — общие стили страниц разделов и пустых состояний.
- `js/telegram.js` — интеграция с Telegram Mini Apps API.
- `js/menu.js` — логика открытия, закрытия и навигации меню.
- `js/profile.js` — имя, аватарка и баннер профиля.
- `js/storage.js` — локальное сохранение имени и изображений.
- `js/events/data.js` — каталог опубликованных событий.
- `js/events/read-state.js` — отметки просмотренных событий.
- `js/pages/event-card.js` — единый шаблон карточки события и таймер.
- `js/pages/` — отдельные модули содержимого страниц.

## Главная страница

Главная пока оставлена пустой намеренно — следующий вариант интерфейса будет выбран после обсуждения структуры и функций.

## События

Все опубликованные события описываются объектами в `js/events/data.js`. Каждое событие использует общий горизонтальный баннер из `js/pages/event-card.js`: необязательное фоновое изображение, название, описание, дата окончания, текстовый таймер и кнопка участия. Если у события ещё нет изображения, фон автоматически использует тот же цвет-заполнитель, что и пустой баннер профиля. Для добавления нового события достаточно создать объект с уникальным `id` в `js/events/data.js`.

Просмотры сохраняются в localStorage отдельно для Telegram-пользователя на текущем устройстве. Счётчик в меню показывает количество событий, ID которых ещё не отмечены как просмотренные. Между устройствами данные пока не синхронизируются.

## Маршруты

- `#/` — главная.
- `#/profile` — профиль.
- `#/events` — текущие события.
- `#/servers` — сервера.

Меню имеет фиксированный порядок: «Главная», «Профиль», «События», «Сервера», «Human Glaze». Все пункты остаются видимыми; текущий раздел выделяется фоном. Human Glaze пока отключён и помечен как «скоро».

## Публикация

Проект публикуется как статический сайт GitHub Pages из корня ветки `main`. Сборка и пакетный менеджер не требуются: браузер загружает ES-модули напрямую.

После изменения JavaScript или CSS обновляйте query-параметр версии в `index.html` и соответствующих импортах модулей, чтобы Telegram WebView не использовал старые ресурсы из кэша.

## Текущие ограничения

Приложение пока не имеет backend. Имя и изображения профиля хранятся локально на устройстве; списки событий и серверов пока показывают пустые состояния. Для общих данных и синхронизации между устройствами понадобится серверная часть.
