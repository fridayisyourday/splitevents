## Как устроен проект

- \`index.html\` — HTML-каркас приложения и подключение стилей и модулей.
- \`app.js\` — запуск приложения, маршруты и соединение модулей между собой.
- \`css/base.css\` — общие дизайн-токены, цвета, размеры, типографика, светлая/тёмная тема и сброс браузерных стилей.
- \`css/components.css\` — единая система кнопок и их вариантов: основная, вторичная, иконная и навигационная.
- \`css/layout.css\` — шапка, основная область и безопасные отступы Telegram.
- \`css/pages.css\` — общий каркас страниц, заголовки и пустые состояния.
- \`css/menu.css\`, \`css/profile.css\`, \`css/events.css\` — стили соответствующих компонентов.
- \`css/awards.css\` — адаптивная тема виджета Friends Awards, использующая общие цветовые и размерные токены приложения.
- \`js/telegram.js\` — интеграция с Telegram Mini Apps API и синхронизация цветовой темы.
- \`participate.html\`, \`js/participate.js\` — отдельная страница участия, открываемая из карточки события.
- \`js/awards-widget.js\` — механика номинаций Friends Awards для события SQUASH!.
- \`js/menu.js\` — боковая навигация.
- \`js/profile.js\` — имя, аватарка и баннер профиля.
- \`js/storage.js\` — локальное сохранение имени и изображений профиля.
- \`js/pages/page-shell.js\` — единый каркас страниц и общий элемент пустого состояния.
- \`js/pages/empty-state.js\` — рендерер пустых страниц на общем каркасе.
- \`js/pages/event-card.js\` — единый шаблон карточки события и обратный отсчёт.
- \`js/pages/events.js\`, \`js/pages/servers.js\` — содержимое разделов событий и серверов.
- \`js/events/data.js\` — каталог опубликованных событий.
- \`js/events/storage.js\` — общий адаптер локального хранения списков ID.
- \`js/events/active-state.js\` — подсчёт активных событий, которые пользователь не скрывал.
- \`js/events/hidden-state.js\` — скрытие событий для конкретного пользователя на текущем устройстве.

## Единые правила интерфейса

Страницы разделов собираются через \`page-shell.js\`. Поэтому у «Событий» и «Серверов» один размер заголовка, одинаковые отступы и одинаковое вертикальное положение пустого состояния.

Кнопки используют общий класс \`ui-button\` и визуальные варианты. Компоненты задают только расположение, не дублируя базовую типографику, высоту, отступы и состояния. Кнопки голосования тоже используют общую систему: основное действие — \`ui-button--primary\`, вторичное или выбранное состояние — \`ui-button--secondary\`.

Общие размеры, цвета, типографика, интервалы и скругления находятся в \`css/base.css\`. Повторно используемые стили кнопок — в \`css/components.css\`. Цвета компонентов берутся из токенов Telegram; при обычном открытии в браузере используются системные светлая и тёмная темы.

## События

События описываются объектами в \`js/events/data.js\`. Каждое использует один шаблон карточки из \`js/pages/event-card.js\`. Даты на карточках показываются в числовом формате \`ДД.ММ.ГГГГ\`. Для добавления будущего мероприятия достаточно добавить запись с уникальным \`id\`, названием, описанием и датами. Фоновое изображение необязательно.

Событие можно скрыть кнопкой с открытым глазом. В режиме «Показать скрытые» скрытая карточка получает кнопку с перечёркнутым глазом: нажатие возвращает событие в обычный список. Кнопка переключения скрытых карточек располагается по центру под списком или пустым состоянием. Скрытые ID сохраняются в localStorage отдельно для Telegram-пользователя на текущем устройстве. Между устройствами эти данные пока не синхронизируются.

Счётчик рядом с пунктом «События» показывает количество активных событий, которые пользователь не скрывал. Срок активности определяется полем \`endsAt\`. Просмотр события и старые отметки о просмотре на счётчик не влияют. Если активных и видимых событий нет, счётчик скрыт.

## Страница SQUASH! и Friends Awards

Кнопка «Принять участие» открывает \`participate.html?event=...\`. Страница проверяет ID события по каталогу \`js/events/data.js\`; виджет премии отображается для события \`squash-award-2026\`.

Виджет переносит механику исходного Friends Awards:
- индивидуальные номинации PUMPKIN KING и PUMPKIN QUEEN;
- выбор пары в DUO ГОДА;
- выбор изображения или свободного предложения в DRIP ГОДА;
- фиксированный список NEXTGEN;
- добавление участника из общего пула в индивидуальные номинации, где это разрешено;
- постраничный выбор кандидатов и обязательный выбор во всех пяти номинациях.

Список участников, пары и предварительно заданные кандидаты находятся в \`js/awards-widget.js\`. Изображения в исходном файле не заданы, поэтому до добавления аватаров показываются аккуратные инициалы.

**Ограничение текущей версии:** виджет собирает объект бюллетеня в браузере, помещает его в \`window.FRIENDS_AWARDS_LAST_SUBMISSION\` и отправляет событие \`friends-awards:submit\` для будущего серверного обработчика. Он пока не отправляет и не сохраняет голоса на сервере, а выбор не синхронизируется между устройствами. После подключения backend этот обработчик можно связать с общей системой голосования.

## Маршруты

- \`#/ \` — главная.
- \`#/profile\` — профиль.
- \`#/events\` — текущие события.
- \`#/servers\` — сервера.

Меню имеет фиксированный порядок: «Главная», «Профиль», «События», «Сервера», «Human Glaze». Все пункты остаются видимыми; текущий раздел выделяется. Human Glaze пока отключён и помечен как «скоро».

## Публикация и ограничения

Проект публикуется как статический сайт GitHub Pages из корня ветки \`main\`. Сборка и пакетный менеджер не требуются: браузер загружает ES-модули напрямую.

После изменения CSS или JavaScript обновляйте query-параметры версий в HTML и соответствующих импортах модулей, чтобы Telegram WebView не использовал старые ресурсы из кэша.

Приложение пока не имеет backend. Профильные изображения хранятся в IndexedDB, имя и состояние событий — в localStorage. Список событий задаётся статически в проекте; для совместного участия пользователей, синхронизации голосов между устройствами и реального приёма бюллетеней понадобится серверная часть.
