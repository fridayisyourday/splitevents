# SplitEvents

Telegram Mini App для организации совместных мероприятий.

## Структура проекта

```text
/
├── index.html
├── app.js
├── README.md
├── css/
│   ├── base.css
│   ├── components.css
│   ├── events.css
│   ├── layout.css
│   ├── menu.css
│   ├── pages.css
│   └── profile.css
└── js/
    ├── telegram.js
    ├── menu.js
    ├── profile.js
    ├── storage.js
    ├── events/
    │   ├── data.js
    │   ├── hidden-state.js
    │   ├── read-state.js
    │   └── storage.js
    └── pages/
        ├── empty-state.js
        ├── event-card.js
        ├── events.js
        ├── page-shell.js
        └── servers.js
```

## Как устроен проект

- `index.html` — HTML-каркас приложения и подключение стилей и модулей.
- `app.js` — запуск приложения, маршруты и соединение модулей между собой.
- `css/base.css` — общие дизайн-токены, цвета, размеры, типографика и сброс браузерных стилей.
- `css/components.css` — единая система кнопок и их вариантов: основная, вторичная, иконная и навигационная.
- `css/layout.css` — шапка, основная область и безопасные отступы Telegram.
- `css/pages.css` — общий каркас страниц, заголовки и пустые состояния.
- `css/menu.css`, `css/profile.css`, `css/events.css` — стили соответствующих компонентов.
- `js/telegram.js` — интеграция с Telegram Mini Apps API.
- `js/menu.js` — боковая навигация.
- `js/profile.js` — имя, аватарка и баннер профиля.
- `js/storage.js` — локальное сохранение имени и изображений профиля.
- `js/pages/page-shell.js` — единый каркас страниц и общий элемент пустого состояния.
- `js/pages/empty-state.js` — рендерер пустых страниц на общем каркасе.
- `js/pages/event-card.js` — единый шаблон карточки события и обратный отсчёт.
- `js/pages/events.js`, `js/pages/servers.js` — содержимое разделов событий и серверов.
- `js/events/data.js` — каталог опубликованных событий.
- `js/events/storage.js` — общий адаптер локального хранения списков ID.
- `js/events/read-state.js` — отметки просмотренных событий и счётчик новых.
- `js/events/hidden-state.js` — скрытие событий для конкретного пользователя на текущем устройстве.

## Единые правила интерфейса

Страницы разделов собираются через `page-shell.js`. Поэтому у «Событий» и «Серверов» один размер заголовка, одинаковые отступы и одинаковое вертикальное положение пустого состояния.

Кнопки используют общий класс `ui-button` и визуальные варианты. Компонент может задавать только свою роль и размер, но не создаёт собственный несвязанный стиль кнопки.

Общие размеры, цвета, типографика, интервалы и скругления находятся в `css/base.css`. Повторно используемые стили кнопок — в `css/components.css`.

## События

События описываются объектами в `js/events/data.js`. Каждое использует один шаблон карточки из `js/pages/event-card.js`. Для добавления будущего мероприятия достаточно добавить запись с уникальным `id`, названием, описанием и датами. Фоновое изображение необязательно.

Событие можно скрыть кнопкой с глазом. Просмотренные и скрытые ID сохраняются в localStorage отдельно для Telegram-пользователя на текущем устройстве. Между устройствами эти данные пока не синхронизируются.

Счётчик в меню показывает опубликованные события, которые пользователь ещё не открывал. Скрытие карточки не удаляет само событие из общего каталога.

## Маршруты

- `#/ ` — главная.
- `#/profile` — профиль.
- `#/events` — текущие события.
- `#/servers` — сервера.

Меню имеет фиксированный порядок: «Главная», «Профиль», «События», «Сервера», «Human Glaze». Все пункты остаются видимыми; текущий раздел выделяется. Human Glaze пока отключён и помечен как «скоро».

## Публикация и ограничения

Проект публикуется как статический сайт GitHub Pages из корня ветки `main`. Сборка и пакетный менеджер не требуются: браузер загружает ES-модули напрямую.

После изменения CSS или JavaScript обновляйте query-параметры версий в `index.html` и соответствующих импортах модулей, чтобы Telegram WebView не использовал старые ресурсы из кэша.

Приложение пока не имеет backend. Профильные изображения хранятся в IndexedDB, имя и состояние событий — в localStorage. Список событий пока задаётся статически в проекте; для совместного участия пользователей и синхронизации между устройствами понадобится серверная часть.
