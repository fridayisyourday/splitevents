# Архитектура SplitEvents

## Принцип организации

Проект — статическое Vue 3 приложение, собираемое Vite. Компоненты Vue хранят шаблон и логику рядом в `.vue` файлах; GitHub Pages получает готовую сборку из `dist/`. Шапка, боковая навигация, все страницы и интерактивный интерфейс голосования реализованы Vue-компонентами. Единые функции разбора и генерации hash-маршрутов находятся в `js/navigation.js`; правила номинаций и расчёты бюллетеня остаются в независимых JS-модулях.

## Точка входа и оболочка

- `index.html` содержит метаданные, Telegram SDK и точку монтирования Vue.
- `src/main.js` создаёт Vue-приложение и монтирует `src/App.vue`.
- `src/App.vue` формирует Vue-оболочку, реактивное переключение страниц и интеграцию Telegram. Общие `getCurrentPage()`, `getPublicUserId()` и `getPageHash()` находятся в `js/navigation.js`, чтобы компоненты использовали одинаковые правила маршрутизации. `NotificationRegion.vue` отдельно управляет отображением уведомлений; прямое DOM-переключение страниц удалено.
- `src/components/AppHeader.vue` — Vue-компонент шапки и боковой навигации. Он управляет открытием/закрытием меню, фокусом, доступностью, текущим разделом и счётчиком событий.
- `src/components/ProfilePage.vue` владеет состоянием собственного профиля, редактированием имени, загрузкой аватара и баннера, локальным кэшем и синхронизацией с Telegram/Cloudflare API.
- `src/components/FriendsPage.vue` загружает авторизованный каталог друзей, сортирует его по алфавиту, показывает состояния загрузки/ошибки/пустого списка и открывает публичный профиль выбранного человека.
- `src/components/UserProfilePage.vue` загружает публичный профиль по случайному `public_id` и показывает его имя, Telegram-тег, баннер и аватар без действий редактирования.
- `src/components/EventsPage.vue` владеет карточками событий, локальным скрытием, обратным отсчётом и счётчиком активных событий в меню.
- `src/components/HomePage.vue` и `src/components/ServersPage.vue` владеют разметкой главной и пустого состояния серверов.
- `src/components/NominationsPage.vue` управляет состоянием голосования, каруселью номинаций, окнами выбора, пагинацией и доступностью диалогов.
- `src/components/NominationCard.vue` отображает карточку номинации и выбранный результат.
- `src/components/NomineeVisual.vue` показывает аватары, изображения и безопасные текстовые заглушки.
- `src/components/NotificationRegion.vue` отображает уведомления об ошибках и предупреждениях.
- `js/telegram.js` изолирует Telegram Mini Apps API: тему, безопасные зоны, viewport и BackButton.

## Данные и локальное хранение

### Номинанты

`js/nominations/database/` — единственный источник статических записей о людях и правилах допуска к номинациям.

- `nominees.js` — каталог людей, сортировка и индекс по ID.
- `definitions.js` — определения номинаций, допустимые ID и пары DUO.
- `validate.js` — проверка уникальности идентификаторов и ссылочной целостности каталога.

Каталог не является серверной базой данных: это редактируемые исходные данные приложения. Проверка в `definitions.js` выполняется при загрузке модуля и обнаруживает опечатки до того, как они приведут к неполным спискам выбора.

### Голосование

- `js/nominations/state.js` создаёт независимую копию начального состояния для виджета. Это состояние не изменяет определения в базе.
- `js/nominations/model.js` содержит чистые вычисления: допустимость выбора, пары, завершённость бюллетеня и его локальный снимок.

Vue-страница предоставляет `getBallot()`, `isComplete()` и `getSnapshot()` для чтения локального состояния. Результаты по-прежнему существуют только в памяти текущего запуска: серверной отправки, долговременного хранения голосов и синхронизации между устройствами нет.

### События, друзья и профиль

- `js/events/data.js` — неизменяемый каталог событий.
- `js/events/storage.js` — адаптер localStorage для наборов ID.
- `js/events/hidden-state.js` — скрытые пользователем события.
- `js/events/active-state.js` — чистые расчёты активных событий и ближайшего срока.
- `src/components/EventsPage.vue` — шаблон карточек, таймеры, скрытие событий и обновление счётчика активных событий.
- `src/components/FriendsPage.vue` — список друзей и переход к публичному профилю.
- `src/components/UserProfilePage.vue` — публичное представление профиля.
- `src/components/HomePage.vue` и `src/components/ServersPage.vue` — главная и страница серверов.
- `src/components/NominationsPage.vue` — реактивное состояние страницы голосования и диалогов.
- `src/components/NominationCard.vue` — карточки основных и дополнительных номинаций.
- `src/components/NomineeVisual.vue` — аватары, изображения и fallback-представление.
- `js/media.js` — единое построение адресов и проверка изображений из ImageKit; `js/pages/profile-presentation.js` — дополнительная проверка профильной папки.
- `js/storage.js` — localStorage для имени и IndexedDB для локального кэша изображений профиля.

Отображаемое имя профиля синхронизируется с сервером и дополнительно зеркалируется в localStorage для быстрого отображения. Аватар пользователя хранится в D1 как подтверждённый Telegram photo_url до первой собственной загрузки; после неё приоритет получает изображение ImageKit и его file ID. Баннер сохраняется в ImageKit. IndexedDB используется только как локальный кэш и fallback. Скрытые события — в localStorage.

### API и серверное хранение

- `js/api.js` отправляет запросы к Cloudflare Worker.
- `worker/index.js` проверяет подпись Telegram `initData` с помощью bot-token HMAC и только после успешной проверки читает или обновляет запись текущего пользователя в D1.
- Worker выдаёт CORS-доступ только origin GitHub Pages. CORS ограничивает браузерный доступ, но не заменяет проверку подписи Telegram.
- Загрузка `/api/profile/media` принимает только аватар или баннер, проверяет подпись Telegram `initData`, MIME-тип, сигнатуру содержимого и размер до 5 МБ. Worker загружает файл в ImageKit server-to-server в папку `/splitevents/profile`; приватный ключ `IMAGEKIT_PRIVATE_KEY` не передаётся браузеру.
- D1 хранит URL и file ID изображений профиля. При замене старый файл удаляется из ImageKit после успешной записи нового; миграция `worker/migrations/0002_profile_media_file_ids.sql` добавляет нужные поля.
- Миграция `worker/migrations/0003_public_user_ids.sql` добавляет случайный стабильный `public_id` и уникальный индекс. Он используется в маршрутах чужих профилей вместо Telegram ID.
- `POST /api/friends` и `POST /api/user` требуют подписанный Telegram `initData`. Каталог исключает текущего пользователя на стороне Worker; ответы не раскрывают Telegram ID и содержат только публичные поля профиля.
- Серверная запись пользователя содержит Telegram-идентификатор и поля профиля. Клиент не может передать чужой Telegram ID вместо подтверждённого ID из `initData`.
- Синхронизация голосов пока не реализована: выбор номинантов существует только в памяти виджета.

## CSS-слои

- `base.css` — reset, базовая типографика, доступность и системное скрытие `[hidden]`.
- `design-system.css` — палитра тем, дизайн-токены и общие правила компонентов. Подключается после компонентов, поэтому массовые `!important` не нужны.
- `notifications.css` — адаптивные уведомления, использующие те же токены темы, радиусы и тени.
- `components.css` — базовые стили кнопок.
- `layout.css`, `pages.css` — оболочка и общий каркас страниц.
- `menu.css` сохраняет оформление Vue-шапки и бокового меню; `profile.css` — внешний вид Vue-профиля; `friends.css` — каталог друзей и публичного профиля; `events.css` — стили Vue-страницы событий.
- `nominations.css` — базовая структура и общие элементы голосования.
- `nominations-carousel.css` — геометрия и анимации карусели.
- `nominations-picker.css` — окна и сетка выбора номинантов.
- `nominations-cards.css` — композиция карточек номинаций, изображения и нижняя информационная панель.

CSS-файлы подключаются в порядке каскада. При переносе правил сохраняйте порядок ссылок в `index.html`: поздние модули содержат уточнения для предыдущих.

## Публикация и кеш

Vite собирает приложение в `dist/`; для GitHub Pages установлен base path `/splitevents/`. Публикация выполняется GitHub Actions. В настройках репозитория Settings → Pages источником должен быть выбран GitHub Actions.

Vite формирует production-имена JS/CSS-файлов с хешами, поэтому для новых Vue-модулей ручное увеличение `?v=...` не требуется. Старые модули временно сохраняют прежние query-параметры до миграции.

Для проверки запускаются `npm run check`, `npm test` и `npm run build`. Скрипт `check` использует `node --check` для JS/MJS-файлов приложения и Worker; встроенный Node test runner проверяет hash-маршруты, безопасность URL изображений профиля, расчёты активных событий, целостность базы номинантов и модель бюллетеня; Vite build компилирует Vue SFC и собирает приложение. GitHub Actions выполняет все проверки для pull request и публикует production-сборку из `dist/` после push в `main`.

## Известные ограничения

- Серверный backend поддерживает профиль, каталог друзей и чтение публичных профилей; синхронизация голосования ещё не реализована.
- Каталог номинантов и событий статический и обновляется через Git.
- Статическая проверка исходников не заменяет визуальную проверку в обычном браузере и Telegram WebView.


## Изображения сайта и ImageKit

Все управляемые сайтом изображения обслуживаются через единый модуль `js/media.js`. Он строит адреса в ImageKit endpoint `ik.imagekit.io/splitevents` и отклоняет URL, которые не принадлежат этому endpoint или ожидаемой папке.

- Профиль: загрузка аватара и баннера через Cloudflare Worker в `/splitevents/profile`. Эти файлы повторно используются в каталоге друзей и публичных профилях.
- События: обложка каждого события из `/splitevents/events/<event-id>/cover.webp`.
- Номинанты: портреты и изображения участников из `/splitevents/nominees/<nominee-id>.webp`.
- Серверы: широкая обложка `/splitevents/servers/<server-id>/banner.webp` и три слайда `gallery-01.webp` — `gallery-03.webp` в той же папке.

Папки и имена файлов перечислены в `docs/media-library.md`. GitHub Pages загружает изображения напрямую из ImageKit; приватный ImageKit API key остаётся только в секретах Worker.
